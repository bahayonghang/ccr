# Product

## Register

product

## Users

CCR UI is for advanced AI CLI power users who configure, switch, monitor, and repair several local AI toolchains in the same work session. They manage Claude Code, Codex, OpenCode, Antigravity and Gemini compatibility paths, MCP servers, agents, plugins, sync, runtime state, and usage data from a desktop-first control surface.

These users value fast scanning, truthful state, explicit scope, and operational control. They are comfortable with dense configuration and need the interface to protect real local files, credentials, and backups while keeping common workflows quick.

## Product Purpose

CCR UI is the desktop workbench for managing AI CLI environments. It provides configuration editors, auth and profile surfaces, MCP and agent management, plugin workflows, controlled command execution, sync and backup flows, usage analytics, and runtime monitoring over a Tauri backend.

Success means a user can inspect state, make a scoped change, understand risk, verify the result, and recover from local runtime failures without losing configuration or confusing browser-runtime limitations with desktop behavior.

## Brand Personality

Calm, precise, editorial.

The product should feel purpose-built, quiet, and trustworthy under high information density. It should resemble an Anthropic-like operational workbench for expert users, not a generic SaaS dashboard or a decorative AI toy.

## Anti-references

Avoid generic SaaS admin styling, loud purple or purple-blue tech gradients, heavy Liquid Glass or glassmorphism as decoration, mascot-heavy novelty, catgirl or NEKO branding, guofeng styling, anime atmospherics, beginner-facing simplification that hides operational detail, and motion that performs instead of communicating state.

Existing legacy `guofeng`, `neko`, anime, and heavy-glass branches are not parallel design languages. Treat them as migration surfaces to retire over time.

## Design Principles

1. Power-first density: preserve expert scanning speed and avoid simplifying away real configuration scope.
2. Truthful operational state: distinguish backend state, web-preview limitations, loading, warnings, failures, and destructive actions clearly.
3. One visual language: converge on the calm editorial surface and do not add new guofeng, neko, anime, purple-tech, or decorative glass variants.
4. Safety before automation: protect local tool config, tokens, backups, and destructive command paths with explicit state and confirmations.
5. Distinctive restraint: express identity through precise typography, restrained surfaces, meaningful color, and consistent component vocabulary.

## Accessibility & Inclusion

Support both light and dark themes with high contrast. Treat WCAG AA contrast as the baseline for text, controls, placeholders, and status labels. Preserve keyboard navigation, visible focus states, native control semantics, reduced-motion compatibility, and clear disabled, loading, error, and empty states.
