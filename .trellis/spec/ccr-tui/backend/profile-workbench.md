# Profile Workbench

## 1. Scope / Trigger

Changes to Codex, Claude or Grok Profile loading, mutations, table geometry, runtime strips, last-use data or the shared A detail panel must preserve this contract. Auth account workflows keep their existing owners. `profile_tasks.rs` schedules work; `app.rs` consumes typed outcomes; `ui/workbench.rs` renders cached snapshots.

## 2. Signatures

- `ProfileTasks::{request_read, start_mutation, drain, ready_to_exit}`.
- `MutationRequest::{Apply(ApplyProfileRequest), Off(Platform), Edit(Box<EditRequest>), Create(Box<CreateRequest>)}`.
- `ProfileEditor` (`EditorMode::{Create, Edit}`) collects a draft. `EditorEvent::{Save, Cancel, None}` is the only signal `app.rs` routes. `n` opens `Create`, `e` opens `Edit`; `Ctrl+S` then `y` schedules `Create` or `Edit`.
- `TuiApp::{poll_background, has_pending_work, ready_to_exit}` supplement `on_tick`.
- `EventHandler::{poll_event, take_tick_due}` separates completion polling from periodic timers.
- `TableGeometry` owns header, rule, body and columns; `App::list_area` stores the body Rect, not the outer border.
- Activity DTOs come through the [read-only activity facade](../../ccr-store/backend/profile-activity.md); usage comes through the existing `UsageApp`.

## 3. Contracts

- Construct the configured tab shell without synchronously loading every platform. Start the active Profile read first; initialize other Profile tabs on first visit. Selection/rendering use cached data only. Explicit reload and completed mutations refresh the affected platform.
- Permit one mutation at a time, with the original platform/name/operation ID captured before scheduling. Execute the entire existing synchronous apply/off/edit/create lifecycle in a blocking worker without acquiring `operation_lock` on the TUI main thread. Preserve committed warnings, recovery outcomes, backup, CAS and the thread-local journal.
- Profile Apply (`Enter` / `Space`) and Profile Off (`o`) open a default-cancel confirmation before any writer starts. Schedule `MutationRequest` only after `y`. Freeze the Apply platform and profile name when the dialog opens; `y` must not read the cursor again. While that confirmation is open, repeated keys must not start another writer. Account switch and official logout stay with the Auth apps.
- Profile create (`n` / `N`) is bound only inside the Profile tab key map (never globally across Auth tabs, preserving `CodexAuthApp`'s `n` account rename). It opens `ProfileEditor` in `EditorMode::Create` only when the Profile tab is loaded, has no in-flight mutation, has no open confirmation, and has a valid `catalog_revision` (`CcrError::ConfigMissing` maps to `Some("")` without creating files on disk; corrupt/unreadable catalogs yield `None`, unconditionally clear stale `tab.catalog_revision`, and block `n` and `Ctrl+S` with a reload/validate error). `Create` exposes progressive-disclosure auth/credential selectors (`Claude`: `api_key` | `subscription`; `Codex`: `provider_bearer_token` | `provider_env_key` | `openai_api_key` | `openai_chatgpt` | `no_auth` with explicit `auth_mode`; `Grok`: `api_key` | `env_key` | `session`). Toggling modes preserves hidden text buffers in memory while `build_create` emits only fields valid for the selected mode. Secret fields render `'•'` dots (`‹empty›` / `‹未填写›` when empty or whitespace-only, `Ctrl+D` clears immediately), `base_url` preview rows pass through `GrokPlatform::safe_base_url_for_display`, and both the `New profile` preview and `ConfirmGate` (`ConfirmKind::Save`) report secrets strictly as `‹set›` / `‹unset›` while stating that creation does not activate/switch the current runtime (without embedding key hints inside the preview panel). On failure (`ResourceAlreadyExists`, CAS version conflict, lock/I/O), the worker synchronously reads the fresh catalog revision/names (`SyncedCreateCatalog`), switches `active_tab` back to the originating Profile tab, sanitizes `CcrError` diagnostics so TOML/JSON source snippets and URL userinfo never leak, and restores the suspended `Create` draft and secret buffer with fresh `expected_revision` and `existing_names` (focusing `name` on external same-name collisions) so immediate `Ctrl+S` -> `y` retries cleanly. On `MutationOutcome::Created`, runtime remains untouched and selection aligns to the new profile via `align_selection_by_name` on the matching platform (or updates `saved_selection` if the user switched tabs while creating).
- Profile edit (`e`) opens only on a Profile tab with a selection, a known catalog revision, no in-flight mutation, and no open confirmation. Auth tabs ignore `e`. The editor records the revision from the snapshot (`ConfigManager` on the read worker, stored on the tab). `Ctrl+S` validates locally, then opens a default-cancel save confirmation that lists changed field names. Secrets say replaced or will-clear and never include the value. `y` schedules `MutationRequest::Edit` with `ApplyPolicy::IfCurrent` and the revision captured when the editor opened; it does not read the cursor again. Model fields cycle with `←→` through the platform catalog. Codex starts the list at `gpt-6.1-sol` (shown as 6.1 Sol · default) and includes `gpt-6-astra`; Claude starts at `claude-opus-5-5`. The recommended id is not written until the user selects it. Typing, pasting, or Backspace switches that field to a custom id and does not rewrite an untouched current value. While the editor is open, `q`, `h/j/k/l`, `n`, `o`, `r`, and `x` are ordinary characters, Tab and header clicks do not change platform tabs, and `Ctrl+C` cancels like Esc instead of quitting. A dirty Esc arms a second Esc to discard. The draft survives resize and background reads. A version conflict keeps the editor and draft open. Grok `RenameApplyFailed` and `RenameCleanupFailed` are warnings, not success, and still refresh. After a successful edit the platform reloads and the selection follows `new_name` on the matching platform tab. Wide keeps the dimmed list (including the dimmed empty-state pane when creating the first profile) and puts the form plus preview in the detail rail. Standard and Compact replace the area between header and footer. Bracketed paste is enabled with raw mode and disabled on every restore path. Paste inserts only while the editor is open, with CR/LF stripped.
- Read generations may discard obsolete snapshots; mutation outcomes are always consumed. Repeated action keys must not create another write. Profile browsing remains available while writing; entering Auth tabs is gated during a Profile mutation.
- q, Esc and Ctrl+C defer exit until the mutation completes. `ready_to_exit` is separate from the redraw return value of `on_tick`. Drain completion channels after every event, including Ctrl+T, resize and ignored mouse motion. Pending work caps event polling at 50 ms; normal timer cadence remains 250 ms even under continuous input. Idle ticks do not force redraws.
- Refresh initialized Auth runtime summaries from the new snapshot without resetting the selected account. A failed runtime refresh cannot leave a cached marker claiming a known effective activation. Grok uses its typed activation inspection, preserving drift and unsafe states.
- The table spends one row on headers and one on a horizontal rule. Pagination and mouse hit-testing consume exactly its body height/origin. Drop optional description/model columns before status/name/last-used; measure CJK and long strings in terminal cells.
- Header compactness follows the measured total tab width, including padding/dividers. Compact Auth labels retain their platform names; render and hit-testing share the same spacing so all six tabs remain identifiable and clickable at supported narrow sizes.
- Wide layout retains the 46/54 split. The detail rail fills the rect assigned to it instead of shrinking to its content. In the wide side-by-side layout its bottom border shares the list's bottom row. Fixed sections are identity, connection, provider usage, then the latest three recorded successful activations. Within one platform and viewport, identity, connection, and usage title rows stay put when the selection changes: connection height is reserved from the platform field set, and an unset field leaves a blank slot instead of pulling the next section up. Empty usage and activation sections are a single ruler line, title on the left and status on the right. Their scope note is rendered once, and only when that section has records. Populated usage still grows, so the activation title that follows it can move. Connection fields use two columns at an inner width of at least 64 and one column below that. Endpoint, key, and values that do not fit a column take a full row. Wrapping and semantic colors stay on the value. The remaining inner height is a stored-field inspector. Its title includes the `profiles.toml` path captured with the snapshot; rendering does not resolve paths. Core fields come first and `platform_data` follows insertion order. `auth_token` and `api_key` render as `‹已设置›` or are omitted; Grok renders no token field, masked or otherwise. `env_key` shows only the variable name. The inspector scrolls independently while the fixed sections fit, using the existing detail scroll offset. If the fixed sections plus one inspector row do not fit, the whole pane scrolls and keeps the scrollbar and `x–y / n` indicator. Expanded details still show unset fields and may enter that whole-pane scroll. The profile runtime strip is 3 rows in every viewport. Compact keeps the unlabeled value line. Standard and Wide put mode, current profile/model, and auth on one labeled line. A table cell with no activation record shows a muted `—`; loading, unavailable, invalid, and future times keep their existing text and color. The footer labels the expand key `x all fields` and shows `n new` and `e edit` on profile tabs. On a non-empty footer narrower than 90 columns, `n` and `e` are dropped before `x` and `o`; on an empty ready profile list, `n new` remains visible even at 80 columns.
- Last used is a recorded successful CCR activation, not the last API request. Unknown, missing, malformed and future records retain distinct presentation. Relative-time labels schedule redraw at their next boundary instead of invalidating every frame. The activation section still says "no record" in words; only the table cell uses `—`.
- Usage totals remain provider/source scoped and all-time, with approximate official-equivalent cost clearly labeled. Bars compare independent category counts with a common maximum and partial-cell resolution; zero and unknown remain different. Narrow panels retain numeric values and scope. No per-selection SQL or new analytics engine.
- Use TUI-local Codex/Claude/Grok names in portable terminal text; the English Claude tab is `Claude Profile`. Do not change global `Platform::icon` consumers or use generic emoji as product logos. Existing masking and safe URL helpers remain mandatory; Grok renders no inline token, even masked.

## 4. Validation & Error Matrix

| Event/state | Required behavior |
| --- | --- |
| Slow initial read | Shell stays responsive; active tab shows loading |
| Refresh races a mutation | Discard old read; consume mutation; refresh affected platform |
| Reload fails with existing list | Keep browsing data and selection; show failure without claiming fresh current state |
| Repeated Apply/Off | One writer and one operation identity |
| Apply/Off key | Confirmation opens first; no writer until `y`; Apply keeps the name captured at open |
| Quit while writing | Wait; consume final outcome; exit without another key |
| Input continues without idle ticks | Completion and elapsed-time timers still advance |
| Missing history / usage | Explicit unavailable or empty state, never fabricated zero timestamps |
| Short/narrow view | Reach final wrapped line; retain primary footer actions |
| Edit key | Open only with a selection, revision, and no writer or confirmation; otherwise toast or ignore |
| Create key (`n`) | Bound only on Profile tabs; open only when loaded, no writer/confirmation, and `catalog_revision.is_some()` (`ConfigMissing` -> `Some("")`, corrupt -> `None` blocked) |
| Version conflict | Keep the editor and draft; Edit asks to refresh with `r`; Create auto-syncs `expected_revision` and `existing_names` from the refreshed snapshot so `Ctrl+S` can retry |
| Secret create/edit | Dots while typing; preview, confirm, toast, and `Debug` omit the sentinel (`Create` shows `‹set›`/`‹unset›` and states runtime is not activated). Grok inspector still renders no token |
| Paste | Strip CR/LF into the focused field only while the editor is open; disable bracketed paste on restore |

## 5. Good / Base / Bad Cases

- Good: selecting a cached Grok profile only changes in-memory details; a delayed Apply preserves that original target even after switching Profile tabs.
- Good: at 160×45 the detail border ends on the list's bottom row for both an empty-usage profile and a profile with usage, and the connection title stays on the same row.
- Base: missing local history shows no record and leaves storage untouched. The table cell is a muted dash, and the empty usage and activation sections are each one ruler line.
- Bad: calling synchronous profile loading in `render`, moving only half the journal to a worker, treating a redraw boolean as exit, or subtracting a border offset twice during mouse hit-testing.
- Bad: cropping the detail panel to its content height, resolving `profiles.toml` during render, or painting a Grok token as text, a mask, or `‹已设置›`.

- Run tests with default parallelism and `--skip export_bindings`. The palette is process-global: export Mocha/Latte fixtures in separate processes instead of toggling themes inside parallel tests.
- Benchmarks report fixture size, build mode, sample count and p50/p95 separately for UI acknowledgement and work completion. Do not turn observational timing into flaky CI thresholds. TestBackend images prove buffer composition, not native-terminal font rendering or private runtime correctness.

## 7. Wrong vs Correct

Wrong: synchronously load every platform on startup, invoke the lifecycle from the Apply or Off key before confirmation, and check its channel only on idle ticks.

Correct: start a bounded read for the active tab, schedule a complete captured mutation, pump results after every event, and render typed cached state with an independent deferred-exit check.
