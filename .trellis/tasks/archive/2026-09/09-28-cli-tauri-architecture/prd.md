## 需求与子任务归属

- R1：所有配置调用者对同一资源使用一致的读改写边界，列表和诊断不隐式修改文件。 责任子任务 T01 / 09-28-config-repository-consistency。
- R2：CLI、TUI 和 Tauri 的 profile 切换具有相同校验、副作用和诚实完成结果。 责任子任务 T02 / 09-28-profile-application-usecases。
- R3：配置页切换和启用恢复可用，并通过显式平台的共享业务接口完成。 责任子任务 T03 / 09-28-tauri-config-adapter。
- R4：CLI 诊断准确区分状态，认证模式校验与实际 apply 一致，脚本可依赖退出码。 责任子任务 T04 / 09-28-cli-diagnostics-contract。
- R5：每次备份有独立身份，OAuth 等敏感状态从写入开始即遵守现有安全持久化契约。 责任子任务 T05 / 09-28-safe-persistence-backups。
- R6：Usage 同步的开始、取消、超时、清理和终态与真实子进程生命周期一致。 责任子任务 T06 / 09-28-usage-job-lifecycle。
- R7：用户离开并返回命令页后可以继续观察和取消正在运行的命令，历史不遗漏终态。 责任子任务 T07 / 09-28-command-workbench-lifecycle。
- R8：设置页仅保存用户修改的字段，保留现有值并呈现平台规定的编辑能力和限制。 责任子任务 T08 / 09-28-settings-lossless-capabilities。
- R9：Grok Auth 查询失败可恢复，Settings 草稿不被刷新覆盖，配置页语言切换实时生效。 责任子任务 T09 / 09-28-frontend-query-error-contracts。
- R10：优化结果可通过跨入口行为和完整桌面门禁验收，规范与可执行契约一致。 责任子任务 T10 / 09-28-architecture-contract-gates。
- R11：控制命令不被无关长操作阻塞，OAuth 登录的 listener、pending、网络和取消具有同一完成责任者。 责任子任务 T11 / 09-28-desktop-control-oauth-lifecycle。
