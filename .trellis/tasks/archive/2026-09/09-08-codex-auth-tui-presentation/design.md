# Codex Auth 页面展示设计

## 边界与数据流

仅修改 `crates/ccr-tui/src/tui/codex_auth/{app,ui}.rs` 及必要的本地测试；允许在主 `tui/ui.rs` 的现有测试模块补真实组合渲染回归，不修改主壳生产布局。后续将稳定展示契约写入 `.trellis/spec/ccr-tui/backend/backend-guidelines.md`。

现有 service → `CodexAuthApp` 的配额缓存、用量 dataset 与账号账本 → 纯渲染。保持账号匹配与账本时间窗算法，不新增 SQL、缓存源、刷新机制、持久化字段或依赖。本任务作为单任务：配额和用量共用同一页面及布局，拆子任务会导致重叠修改。

## D1：剩余配额（R1，AC1）

- 以 `selected_quota()` 为所选账号缓存读取入口，复用现有刷新/错误状态；当前 `crates/ccr-tui/src/tui/codex_auth/ui.rs:911` 先匹配 Idle 会掩盖已有 preview 数据，改为先读取有效缓存，再叠加刷新/错误标记。
- 使用已有 `theme::quota_color`（`crates/ccr-tui/src/tui/theme.rs:634`）的五档颜色，不创建新主题。明确标题“剩余配额 / Quota remaining”；条形实心部分和百分比同色，未填充部分用 muted 色。颜色随剩余量下降而趋向警戒。
- 从数值生成条形，不解析百分比文本；在唯一的展示转换处把条形输入限制到 0..100，避免现有 `crates/ccr-tui/src/tui/codex_auth/ui.rs:1140` 将负数直接转 usize。正常 service 数值保持原义。
- 每窗口紧凑格式为 `5h  ████████░░  80%  重置 2h`；宽屏重置相对时间和绝对时间可单独下一行。条形宽度由可用显示列计算，最低空间保留窗口名、百分比和短重置时间。
- `window_present = Some(false)` 显示“未提供 / Not provided”，不画条；None 显示“窗口未知 / Unknown window”，不推断满额；Some(true) 才按剩余值画条。列表预览同步这个展示判断，账号详情不得与列表矛盾。
- 无缓存：显示已有等待/加载/错误状态；有缓存刷新：保留条形并标“刷新中”；刷新失败仍有缓存：保留旧值并同时显示失败，不能装作成功。通过 `fetched_at` 显示配额获取时间，不新增“过期”派生标签或阈值；现有列表缓存刷新机制保持不变。认证 `last_refresh` 若保留则单独标“认证刷新”，不得混淆。
- 不改 primary/secondary 的服务端窗口映射。截图中的 5h 行重置为多天只能记录为待运行时核实，不能仅凭截图重写时间戳或窗口类型。

## D2：范围说明与真实警告（R2，AC2）

见 `research/usage-attribution.md`。当前 `fallback_reason` 同时承载普通说明和回退原因；此次无需扩展 schema 或新造分类器，直接使用已有 `attribution_state` 选择说明样式。

- AccountAttributed：以现有筛选结果生成统计，说明使用 muted/info 样式。仅有排除记录时显示准确文案“仅统计可归属此账号的本地记录；其他账号及未归属记录不计入”。不从全局数量差推断缺失历史或损坏。
- UnattributedFallback / VirtualAccount：全局数字仍按现有行为展示，范围行明确“全局本地用量（非所选账号）”，警告保留原有原因信息。GlobalOnly 为中性全局统计。
- UsageState::Error 与配额请求错误保持错误语义；不能统一降级所有黄色文字。范围行是数字的必需前提，无法容纳时先隐藏数字，不得留下没有范围的统计。
- 不增加历史回填或变更 `records_for_account` 的时间窗口匹配。其他账号记录正常被排除；包含未归属历史的统计仍保持子集，不能用全局总量冒充账号总量。

## D3：布局与信息层次（R3/R5，AC3）

沿用现有 ViewportMode 断点。宽屏初始按左右 50/50 分配（现为 60/40）；右侧最少留约 60 显示列，在受限高度下优先分配核心数据，不把单账号列表拉宽到挤压详情。

```text
账号列表                        所选账号 · PRO · 已保存
账号 / 邮箱 / 5h / 7d            已脱敏邮箱 · 认证刷新
                                剩余配额          缓存状态
                                5h ████████░░ 80%  重置…
                                7d ██████░░░░ 60%  重置…
                                ───────────────────────
                                本地用量 · 所选账号
                                范围    Tokens      请求
                                5h       281M       2.2K
                                7d       1.4B      11.0K
                                累计     6.4B      49.5K
                                主要模型：gpt-…
                                仅统计可归属此账号的记录
```

此图仅描述布局，数字为示意，不作为真实账号证据。

- Wide：右上“账号与配额”，高度按元信息、窗口重置行及可见状态计算，正常目标约 12–14 行；右下只放本地用量，不重复配额。账号名/状态/订阅优先，保存日期次要。
- 低高度必须按实际 `content_area.height` 降级，不能仅依赖 ViewportMode：当内容区不足以同时容纳两个右侧卡片时，Wide 的右侧改为一个紧凑详情卡。主壳断点不变；100×22 / 120×22 扣减后均只有 12 行内容。100×22 采用列表 3 行（边框加一个账号、省略列头和列表说明）+ 详情 9 行，详情内 7 行依次容纳两行配额、一行范围、三行无列头核心统计、一行异常/状态；省略主要模型、普通说明与元信息。120×22 左右分栏，右侧合并卡 12 行，核心采用同样内容预算。真实异常优先于次要信息；小于该预算时显示空间不足/省略提示，禁止无范围的裸数字。
- Compact / Standard：沿用上列表、下详情。主壳扣除标题 3 行、footer 2/3 行、runtime banner 3/4 行（`crates/ccr-tui/src/tui/ui.rs:50`、`crates/ccr-tui/src/tui/ui.rs:250`）。80×24 有效内容 16 行，列表 4 行、详情 12 行；100×30 有效内容 20 行，列表 6 行、详情 14 行。列表 4 行含边框、列标题与至少一个账号，底部选择说明在该高度省略。详情 12 行含边框、配额两行、范围一行、统计表四行，剩余三行用于状态和主要模型/说明；Standard 有更多空间时显示详细重置与中性说明。
- 独立命令的真实入口是 `crates/ccr-tui/src/tui/codex_auth/mod.rs:11` → `crates/ccr-tui/src/tui/mod.rs:163` → 主 App，并与主页面共用 `crates/ccr-tui/src/tui/ui.rs:105` 的 `draw_embedded`。因此两入口采用同一壳高度预算。旧 `codex_auth::ui::draw` 不在真实入口路径，本任务不重构其 margin/status/help，也不以它的测试替代生产路径证据。在主 UI 测试模块用注入 CodexAuthApp 的主 App 渲染 fixture 验证实际组合，并保留 auth 初始选中入口的既有测试。
- 真实异常占用预留状态行，必要时省略主要模型、保存日期、中性说明和长绝对时间；保留短重置与核心统计。超长错误文本按显示宽度截断并以省略号明确提示，保持错误类别和关键原因；不承诺在小屏展示任意长错误全文。
- 快捷键只保留现有统一 footer，移除面板内冗长的按键教程；确认弹层/确认提示属于必要交互，仍保留。
- 标签值之间至少一列间距，终端列宽使用 unicode-width；不靠字符计数或固定 12 字符标签造成 `Last refresh:2026` 贴合。
- “已保存/当前启用”是账号状态；本地用量标题明确历史记录范围，与上方实时“未登录”可以同时存在，不改登录状态判定。

## D4：数字与本地用量（R4/R5，AC4）

- 以三行小表格表示 5h、7d、累计，每列右对齐 Tokens 与请求数；主要模型单列、超长按终端列宽省略。
- 数字使用确定性的 K/M/B/T 紧凑单位，边界四舍五入晋级，避免 `6371.2M`；0 和小整数不带无意义小数。只用于本页，不全仓替换格式器。
- 不改 input + output 的现有 token 合计及请求记录计数口径；不把本地 tokens 换算服务端配额。以“本地用量”标题和范围行持续标注数据来源。
