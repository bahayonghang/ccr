# Codex Auth TUI 配额进度与用量信息优化

## Goal

优化用户截图所示的 `ccr tui` Codex Auth 页面：彩色进度条展示所选账号剩余配额，修正本地用量范围说明的警告语义，改善信息层次、空间分配与中英文展示。

## Background

- 以下缺陷来源与源码行号记录规划时的基线 `1ccd1b45`；实施后的结果及验证见 `checks.md`。
- 用户明确要求创建 Trellis 任务并分析、优化页面；当前为 planning，最终方案按 brainstorm 流程确认后实现。起始 `dev` 工作区干净。
- 截图对应 `crates/ccr-tui/src/tui/codex_auth/ui.rs:1329` 的嵌入式 Wide 页面：左 60% / 右 40%，右上固定 13 行，右下混合配额与本地统计。
- `crates/ccr-tui/src/tui/codex_auth/ui.rs:1146` 账号摘要只有百分比和重置时间；另一路 `draw_usage_panel` 已有彩色文本条（同文件第 971 行）。
- 配额字段是剩余百分比，并具有窗口存在标记（`crates/ccr-codex/src/models/codex_auth.rs:778`）。
- 黄色说明的现有条件是全局记录数大于账号归属记录数（`crates/ccr-tui/src/tui/codex_auth/app.rs:634`）；所有说明均使用 warning 样式（`crates/ccr-tui/src/tui/codex_auth/ui.rs:1074`）。这个条件不足以证明被排除记录都属于旧历史或未归属记录，其他账号记录也会触发。

## Requirements

- R1：所选账号的 5h / 7d 剩余配额采用彩色进度条，保留百分比、重置时间和缓存状态；沿用主题余量颜色。窗口明确不存在、加载、错误不能显示成满额或零额。
- R2：账号归属统计的范围说明使用准确、中性的文字；全局回退或真实失败仍突出展示。不得为消除警告而混入其他账号、未归属历史，或把全局用量标为账号用量。
- R3：宽屏左侧账号列表、右上账号与配额、右下本地用量；消除右下重复配额、长篇引导和不合理空白。紧凑/标准布局及独立入口复用相同语义，按空间保留重点。
- R4：本地用量以时间范围 / Tokens / 请求数对齐展示，主要模型单独一行，大数紧凑可读；明确本地记录并非服务端账单或配额消耗计算。
- R5：中英文一致，标签和值有间距，CJK 与长名称按终端显示宽度处理；保留账号选择、分页、覆盖层、已有刷新及语言切换交互。

## Acceptance Criteria

- [x] AC1 (R1)：两种窗口的存在/缺失、缓存/刷新/失败状态可区分；0、低、中、高、100% 的填充和颜色正确，文字明确“剩余”，重置信息可见；列表与详情一致。
- [x] AC2 (R2)：仅有其他账号额外记录时不声称历史缺失；账号归属成功时范围说明中性且说明排除其他/未归属记录；全局回退警告始终与其数字一起出现。过滤结果与原有账本时间窗契约一致。
- [x] AC3 (R3, R5)：TestBackend 覆盖 80×24、100×30、140×40、180×50 的中英文嵌入式页面，以及独立入口；配额、统计范围、核心数字和单行真实错误可读，无边框覆盖。小于支持尺寸时优先范围/异常/配额/核心统计，允许省略次要元信息。
- [x] AC4 (R4, R5)：5h / 7d / 全时段保持现有本地统计口径，数值列对齐，长名称带省略号；“未登录”与“已保存账号存在本地历史”不再通过含混标签制造冲突。
- [x] AC5 (R1, R2, R3, R4, R5)：相关回归测试、TUI crate 测试、usage crate 测试、格式及严格 lint 通过；使用隔离 fixture，不访问个人认证文件。真实终端视觉证据缺失时单独标为 UNVERIFIED。

## Out of Scope

- 登录修复、Token 轮换、账号迁移、历史回填、猜测未归属记录的账号、修改上游配额解析/窗口时长、新增依赖或配置。
- React/Tauri UI、其他 Auth 页面改造、主 TUI 运行时状态条架构变化。
- 提交、推送、发布、读取个人凭证、调用真实配额 API 或桌面 UI 自动化。
