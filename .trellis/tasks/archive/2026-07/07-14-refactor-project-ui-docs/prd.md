# 重构 CCR 项目与 UI 文档

## Goal

基于当前 `crates/` Rust workspace 与 `ccr-ui/` Vue/Tauri 实现，重构仓库的产品文档与 UI 工程文档，使文档结构、命令、功能说明和维护边界与最新项目状态一致。

## Background

- `docs/` 是面向用户发布的中英双语 VitePress 站点。
- `ccr-ui/docs/` 当前混合长期工程规范、未实施提案、已完成计划和离线分析产物。
- 当前文档审计无法准确区分发布页面与内部维护资料，且只验证少量源码事实。

## Requirements

- 以当前代码、配置、测试和命令帮助为事实来源，不沿用无法验证的旧文档描述。
- `docs/` 作为对用户发布的 VitePress 文档站，保持中文与英文活跃页面一致，并遵守 `docs/AGENTS.md`。
- `ccr-ui/docs/` 作为 UI 工程设计、实现计划和审查资料目录，建立清晰的长期文档与历史资料边界。
- 父任务统一管理信息架构、术语、交叉链接和最终集成验收；两个子任务分别负责 `docs/` 与 `ccr-ui/docs/`。
- 保留现有无关工作树改动，不修改 `AGENTS.md` 与 `ccr-vscode/package-lock.json`。
- UI 历史资料保留在仓库内，统一移动到 `ccr-ui/docs/archive/2026/` 并由索引标明生命周期状态。
- 实施顺序为 UI 工程文档子任务、产品文档子任务、父任务交叉验收；后续子任务不得依赖未记录的目录隐含关系。

## Acceptance Criteria

- [x] 产品文档覆盖当前 CLI/TUI、共享 crates 与桌面 UI 的主要用户能力，且关键说法可追溯到代码或测试。
- [x] `docs/` 的中英文导航、页面集合、内部链接和命令说明通过现有文档审计与构建门禁。
- [x] `ccr-ui/docs/` 的目录结构能区分长期规范、当前计划与历史产物，且内容与当前 UI 架构一致。
- [x] 两套文档在术语、入口和职责边界上没有相互矛盾的描述。
- [x] 两个子任务均独立完成检查，父任务完成交叉一致性审查。
- [x] 根 `docs-check` 能验证 VitePress 构建、产品文档审计和 UI 工程文档审计。

## Out Of Scope

- 不修改 `crates/` 或 `ccr-ui/src*` 的产品行为来迁就文档。
- 不重写历史 changelog，也不编辑 VitePress 生成目录或依赖目录。
- 不提交现有无关工作树文件或构建产物。
