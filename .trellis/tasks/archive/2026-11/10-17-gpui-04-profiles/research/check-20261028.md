## Findings fixed

### Nested confirmation overwrote the outer editor's return focus

`act` previously overwrote the editor's `return_focus` for every nested action.
Opening an editor, keyboard-opening Advanced, dismissing that decision, and
then closing the editor restored a handle belonging to the removed Advanced
button. The rendered regression failed with outside focus `Some(false)`.

The local correction captures the outer return handle only when opening from
`Mode::Closed`. Each `Confirmation` still captures its own immediate trigger.
Thus Escape returns from the decision to Advanced; closing the editor returns
to its original outside trigger. No focus trap implementation or frame-order
mechanism was replaced.

### Grok recovery actions survived a platform change

`set_platform` previously retained `grok_recovery`, `grok_force_delete`, message
and failed state. A real `rename_apply_failed` outcome produces a retry button
whose request takes the current platform. After switching to Claude, that Grok
retry remained rendered and could apply the Grok new-name through the Claude
context. The rendered state-transition regression failed before repair.

On an actual platform change only, clear the previous platform's recovery,
force action and feedback before changing identity. Selecting the same platform
and ordinary Status refresh preserve its durable warning. No request is sent
merely to prove the wrong-platform action: its disappearance is checked before
any side effect can occur.
