## Findings fixed by the implementer after independent review

1. `install_detect::detect` used an uncapped `Command::output()` behind a timeout and relied on kill-on-drop instead of awaited owned-tree cleanup. Its `excerpt` sliced UTF-8 at an arbitrary byte boundary (`"密".repeat(100)` at 256 bytes panics). The repaired probe reads both streams concurrently with a 4096-byte plus one-byte overflow check, a three-second execution timeout and awaited managed-tree cleanup. Excerpts redact before clipping at a valid character boundary. Closed synthetic probes cover stdout/stderr overflow and actual owned-descendant exit.
2. `install_ring_buffer::redact` indexed a mutated string with offsets from the original lowercased string. `token=123456789012345678901234567890 password=secret` could panic after the first replacement shortened the string. It now recomputes offsets against the current string using ASCII lowercasing, preserving UTF-8 positions, then delegates broader structured/header cases to the existing core owner.
3. `install_exec` joined stdout/stderr readers without a deadline after process cleanup. A cleanup failure retaining an open writer could hold the domain slot and native shutdown indefinitely. Both readers now share a cleanup deadline; held readers are aborted and awaited. Reader IO/join failure prevents Success/Cancelled terminal publication and becomes the existing InternalError failure variant. No DTO schema change was introduced.

These findings concern owners directly consumed by the new native path; masking the adapter's displayed text alone would not repair them.

## Findings fixed by the reviewer

- `install_detect::parse_version` could send an unredacted last stdout token into the native retained snapshot. Redacting only after extracting the token was insufficient for `Authorization: Bearer ...` and quoted values containing spaces because their identifying labels had been discarded. The final implementation redacts complete stdout before applying the existing parser. Normal semver and prerelease cases remain covered; redaction may remove the only numeric hint and leave an unknown (`None`) version.
- The legacy install redactor stripped an unspaced Authorization scheme before the core header parser could recognize its credential. Authorization now goes directly to the existing core parser. Its remaining seven legacy patterns still fully mask values, including the generic `key=` form that is intentionally absent from global core sensitive-key semantics. The existing scanner now handles leading value whitespace, single/double quotes, escapes, empty and unterminated values. A table covers every legacy pattern, repeated/Unicode cases, intact safe trailing text and unchanged nonsensitive text. No new global redaction policy or general parser framework was added.
- `ccr-desktop/tests/test_commands.py` let the fake ordinary Cargo fixture consult the host's mbx installation. In this sandbox mbx status failed, so a genuine exit-code propagation assertion incorrectly saw resolver failure 1 instead of fixture exit 23. A fixture-owned mbx status stub identifies a different fixture-owned shim; the fake ordinary Cargo is therefore positively distinguished. The original exit-23 and all production fail-closed resolver checks remain intact. The narrow regression passed before rerunning the full desktop gate.
- The new shell InstallView constructor/navigation tuple needed two mechanical rustfmt changes. Only those formatting differences were applied.
