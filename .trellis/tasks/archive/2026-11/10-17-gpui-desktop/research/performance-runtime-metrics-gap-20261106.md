## Conclusion

There are two implementable native product gaps: bounded real latency sampling/visible sample status, and read-only counts of the native application's retained SSH session authority. Neither needs native GUI acceptance or a live host to implement/test. There is **no existing common active owner** that already supplies Tauri's two p95 values or its cache/SSH-map counters to native: the p95 window is Tauri AppState-local, and the SSH state models differ. The reusable common pieces are the bounded-executor/read-service boundaries, shared usage report owner, shared native SSH Workspace and existing RSS reader. Extract only the small missing observation seams in a later explicit batch.

Tauri's exact Moka cache entry count, disconnected-state-map length and password-map length are implementation-specific facts. Native must not create artificial cache/password maps or duplicate disconnected states solely to reproduce those numbers. Nor can absent latency samples be converted to0 or substituted with S2 rates/command-history durations. The current inventory's blanket partial sentence should be split by semantics when an implementation batch is accepted; native deferral is not a reason to leave all executable source gaps untouched.

It is a bounded rolling sample window, not a time-decayed histogram, full process lifetime or benchmark percentile.

## Recommended next batch, with explicit scope

### A. Real bounded latency observations — implementable now, no GUI sample prerequisite

Minimum reusable owner proposal: a plain `ccr_app::monitoring::LatencyWindow` (or private submodule), capacity2048 and the existing nearest-rank algorithm, with `record(Duration)` and `snapshot() -> {sample_count,p95_ms:Option<f64>}`. No timer thread, registry/framework/new dependency, global singleton or SQL. Capture one owner per Services/AppState so unrelated fixture roots/process data cannot mix. Existing Tauri record wrappers/wire fields retain compatibility if delegated to the same small helper; numeric fault policy must remain explicit and not silently turn absent samples into measured zero.

Define the operation cohort before wiring. For a common cross-app read-service observation, add a minimal observed compatibility seam at `ccr-app::usage::read::read_dashboard_at` (e.g. an additional observed entry accepting the captured sample owner, old wrapper unchanged), then both actual native and Tauri report consumers call it. Time real Instant around the same report body; no ReportClock freeze or new adapter SQL. Label it **usage report/service p95**, expose sample count andNone until actual completed reads. That closes a real product source gap without pretending the existing broad Tauri db_query_p95 field has exactly that new meaning.

If native also wants **operation p95 including queue and work join**, add explicit observation at the existing ccr-app RuntimeHandle completion boundary and show a separately named native scoped metric. Queue admission rejection, cancellation-before-work, domain failure, panic, retained job finalizer and read success need declared inclusion rules. Do not rename this to the existing Tauri Usage handler p95 and claim cross-app equal coverage. The still smaller first batch is the common report/service window plus its visible native sample status; all-runtime job metrics can follow independently.

Files for that first proposal: `crates/ccr-app/src/monitoring.rs`/optional latency submodule/tests, `crates/ccr-app/src/usage/read.rs` plus direct tests, native `runtime/mod.rs`, `runtime/insights.rs`, `runtime/monitoring.rs`, `features/monitoring.rs` and tests; if exposing the same report window in Tauri, its existing service/state/DTO policy must be explicitly coordinated. No loader/clock/S2 producer/persistence change. Do not silently broaden the new native aggregate to sessions/imports/monitoring/SSH and call it the same cohort.

Headless success criteria: empty remainsNone; bounded eviction and known nearest-rank; valid0 distinguishable from no samples; real controlled read populates only its captured owner; errors/cancel follow the chosen inclusion contract; two roots/Services do not mix; no synthetic performance threshold. Controlled fixture reads can prove code now, but valid paired perf samples still require the later harness/native work.

### B. Native SSH retained-state observation — implementable now without any transport

Small owner seam proposal: `Workspace::runtime_metrics() -> WorkspaceMetrics { retained_sessions:usize }`, reading only its session lock, no IDs/host/key/path/token data. Native Monitoring reads `Services.ssh.get()`; no initialized owner means an actual0 retained sessions for this process, not permission to discover a host. Label **retained SSH sessions (0/1)** and keep source policy/capability reason explicit for Benchmark. No Tauri state-map/password-cache parity claim.

Files: shared `ccr-app/src/environments/ssh.rs` and direct fixture tests, native `runtime/monitoring.rs`/Metrics, existing Monitoring display/tests. No live host/connectivity operation is required to test: no owner, injected synthetic Workspace connected/disconnected, failed connect and disconnect transitions can use the already existing fixture transport; assert zero transport invocations for metric reads. Source captures still forbid host fallback. This closes a real native metric visibility gap; password authentication/cache or a Tauri-shaped remembered-state map is outside scope.
