# 设计：导入身份与加密入口评估

用户已确认拒绝冲突输入、保留现有加密导出规则。CLI含凭据导出已经强制加密，TUI无Auth导出入口，Tauri无Auth加密导出API，本轮不新增UI或密码DTO。

拒绝策略：写入前预检整个包的待处理条目；沿用Merge/no-force对已存在条目的跳过语义。P1共享helper从tokens推导身份，与account_id元数据核对，不信任导出元数据；完整键从tokens保存，不输出公开DTO。已知不一致拒绝且不创建目录/备份/写文件，valid-first-invalid-second同样无写入。缺失完整user identity保持P1 NoOp兼容，不猜测身份；API key沿用既有指纹与metadata-only语义。

用户已选择拒绝策略；不增加 warning 字段或修改现有 ImportResult/桌面 DTO。

CLI明文import目前吞service错误；拒绝策略需传播Err以保持非零退出。加密导入复用同一预检。输入校验失败的无副作用保证不等同多文件I/O事务；Tauri对象数组现有逐项提交行为单独记载，不增加跨项事务。

整体输入预检通过后，复用 P1 稳定路径/完整身份凭据锁保护待替换目标。Replace 沿用当前覆盖同名记录的语义，不清空未出现在导入包中的账号。锁集覆盖待写路径、原有身份及输入的完整身份，避免新身份与另一别名的刷新交叉；每个原有路径仍须按各自捕获的身份复核。锁前不创建目标目录/备份；锁后重读注册表、验证初始来源和只读版本，必要来源变化时安全中止。锁序与 P3 一致，不扩展公开 DTO 或通用事务。

来源复核同时比较预检时捕获的原始内容版本。等待锁期间同一身份发生 token 轮换时，导入中止并要求重试，保留已轮换快照；只比较 identity resource 不能识别该变化。重试后的显式 force 替换沿用原有导入语义，不自行增加输入 token 新旧判定规则。
