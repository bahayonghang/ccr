# Reviewer Whitespace Wrapper Failures

Status: REVIEWER_CHECK_WRAPPER_FAIL; no product source changed.

The first final-check wrapper used `git -c core.autocrlf=false diff --check`
for tracked files and the same configuration with `--no-index` for untracked
files. Native tracked exit was 2. Native untracked exits included 3. The
diagnostics reported trailing whitespace on CRLF lines, including the JSON
manifest generated by PowerShell. The wrapper exited 1.

The initial generated log contained 13,591 lines. A later wrapper overwrote
that log, so the full original raw log is not preserved in the workspace.
The tool transcript retains the original command and truncated diagnostic
output. This note records that evidence limit; it is not a raw receipt.

A second probe added `--ignore-space-at-eol`, which did not suppress the
`--check` CRLF diagnostics. The report returned native exit 1 with zero
diagnostics; the manifest returned exit 3 with 590 diagnostics; the generated
log returned exit 3 with 27,182 diagnostics. Wrapper exit was 1.

A third wrapper attempted a PowerShell array of function calls without
parentheses. PowerShell joined `Test-NoTrailingWhitespace` to the first path.
`Resolve-Path` could not find that path and `ReadAllText` rejected null. The
wrapper did not fail on those nonterminating errors and produced an invalid
PASS receipt. That receipt cannot establish whitespace acceptance.

The corrected wrapper must use error-stop behavior, explicit CRLF handling
through Git's `cr-at-eol` whitespace policy, and independent file-path
arguments. The final corrected receipt is a separate file. Raw test and
historical owner receipts are not normalized.
