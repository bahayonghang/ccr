# 设计：备份前置条件与保留池

## 状态

本设计完成源码研究。2026-10-06 用户已确认保留全部旧备份；P1 通过独立检查后按顺序启动。

## 存储合同

在 `ccr-codex` 增加私有共享备份帮助函数，沿用 `auth/backups` 根目录。注册表单独一池，每个账号单独一池；精确识别旧名称的完整账号部分，避免 `foo` 与 `foo_bar` 共池。最新备份内容一致时复用路径并刷新 mtime，命中不清理；同秒不同内容追加序号。采用私有原子写；池操作锁包围选名、写入与保留，独立 backup 也遵守锁顺序。

用户已选择暂不清理。本轮只去重、防覆盖、私有写与可靠备份；不运行保留清理，不修改旧备份字节。去重命中仅刷新匹配备份的 mtime。

## 破坏性操作

沿用 P1 新增的凭据操作锁。删除先锁现有快照资源；重命名锁源与目标的稳定路径和已知完整身份资源，去重并排序，锁后重读注册表与逐路径来源。只读注册表拒绝仍发生在锁文件创建前。锁覆盖备份、快照删除/移动与注册表保存，防止 CCR 配额轮换期间移动快照导致新凭据丢失。锁序为凭据操作锁 → 备份池/注册表锁 → 私有写叶锁；不得重入或反向取锁。

delete：版本/账号验证 → 注册表和存在的快照备份全部成功 → 删除快照 → 更新注册表。force rename：版本/源/目标验证 → 目标快照、源快照、注册表备份全部成功 → 删除目标/移动源 → 更新注册表。存在文件的备份失败必须中止；已成功的备份可以保留。注册表自动写前备份失败同样传播。

破坏性末段在既有注册表写锁内重读、复核版本并完成全部备份与提交。已完成前置备份的 delete/rename 使用窄的已持锁提交入口，不再调用普通 save 触发破坏后的第二次备份。不得在前置备份后释放注册表锁，再无版本保护地覆盖其他写入的未备份前像。普通 save 仍传播自动备份失败，不增加公开跳过备份开关。

备份失败前保持源、目标和注册表字节。最终多文件 I/O 失败不承诺通用事务。保持原错误变体，固定失败前缀不包含凭据或身份键，TUI沿用EN/ZH操作失败前缀。
