# 多账号界面与交互

## 文件所有权

crates/ccr-tui/src/tui/grok_auth/{app,ui,mod}.rs、主 app 的必要路由/生命周期、tui/mod.rs 的 Grok 退出总结、对应构造 fixture 与 TUI 规范。使用服务脱敏 snapshot，不读取凭据文件。主题颜色复用现有 Grok accent，清理 theme 字段归清理子任务。

## 布局

Wide（>=120列且>=22行）：列表55% / 详情45%；Standard（90–119列且>=22行）：列表上、详情下；Compact：列表和选中核心信息优先。40×12 至少显示选中别名/空态、可执行主动作及退出；次要 metadata 可省略，不依靠横向滚动。

列表列：名称、本地会话匹配标记、凭据状态（已保存/本地过期/未知），宽屏增加保存时间。详情显示本地可得邮箱、团队、保存时间、原生到期值、scope 来源（安全文本）；没有订阅或 5h/7d 指标。

“当前会话”展示本地 scope 匹配，不称认证已验证。多个 scope 同时在 runtime 可分别有匹配，不能强行一个全局 current。第三方 profile 只读读取 activation 状态，说明本次不会改变 route。账号过期不自动禁用切换，只提示可能需要官方重新认证。

使用现有 pagination helpers、Rect hit-test、display-width 文本处理。主壳分配 footer 区域，Grok 渲染随状态变化的单一 Keys。动作结果和错误在内容区持续可见，toast 作补充。

## 按键与弹窗

正常状态：↑↓/jk 选择，PgUp/PgDn 分页，鼠标只选中；Enter 打开切换确认，s 保存，d 删除保存项确认，o 全 runtime 登出确认，r 只读刷新；Tab/Shift+Tab 换页，Ctrl+L 语言，q/Esc 退出。

保存：只有一个候选 scope 时直接进入别名输入；多个先显示临时来源列表，再输名；0个展示原生登录指引。别名沿用已有输入长度/命名约束；同名进入明确覆盖确认，不能因用户按过保存就默认覆盖。

保存说明与成功反馈为“将当前账号副本保存到 CCR / 已保存，当前账号可继续使用”，详情可展示服务返回的安全存储路径；默认 ~/.ccr/platforms/grok/auth/accounts.json。保存入口不检查 Grok 退出、不出现结束/重启提示。已确定的停止后生效文案仅用于切换确认，不进入保存流程；不探测或终止 Grok 进程。

确认：默认取消，y 确认、n/Esc 取消，Enter 为取消；无需额外左右选择状态。弹窗列出动作和别名/范围；登出文案清楚区别“所有 runtime 凭据”与“CCR 保存账号”。这是用户产品操作确认，不是 Agent 执行授权。

现有 Overlay::Confirm 渲染硬编码“确认删除”，因此复用其布局辅助/色彩与输入形状，但由 Grok 局部 typed modal 状态渲染正确标题，不为其他 Auth 引入新全局弹窗框架。文案由动作状态即时 i18n 派生，Ctrl+L 后不会保留旧语言文本。

正常换页或鼠标离开 Grok 时清掉未提交的保存输入/来源/确认；输入 Enter 只确认输入，不直接执行不带 revision 的危险操作。服务返回冲突则显示需刷新，旧确认不自动重试。

## 后台与生命周期

复用主壳 AsyncTaskExecutor.spawn_blocking；一个 mutation 在途，读刷新不能与旧结果交错覆盖。用一次在途操作标识和结果通道即可，不引入调度框架；提交时冻结操作目标/revision，返回时更新 snapshot 并按别名恢复选择。

提交后标 Busy，其他 mutation 禁用；resize/语言继续可用。为最小完整语义，Busy 期间阻止换页与 q/Esc 的正常退出，提示等待有界操作完成；完成后解除。Ctrl+C/进程终止属于中断，由原子写和保存前置保证可恢复，不能宣称后台动作一定取消。主壳需要在通用 Tab/mouse 分发前识别 Grok Busy，避免子 app 禁用无效。

未提交弹窗换页取消；提交后不显示“已取消”。关闭/退出只发生在结果收集后，复用 CompletedAction 保存最近动作（增加 Grok typed logout 结果，避免所有动作都输出登出）。

无 executor 时不提交并显示错误；不调用 Disabled.spawn_blocking 后无限等待。每个在途操作使用独立结果通道，主线程只持 receiver；任务异常导致通道断开时解除 Busy 并标结果未知，重新读取状态，不当作成功或取消，也不自动重放。初始化/激活/r 都处理读取错误，保留上一成功 snapshot 并标旧状态；离开页/重入不丢 mutation 结果。事件层已过滤 Repeat/Release，不在多层再做同一探测。

## 验证与边界

TestBackend 用例设计覆盖每种 modal/状态和中英文不同宽高；服务 fake 仅作调用次数/异步顺序测试，临时目录用例负责文件结果。本轮按用户要求仅维护必要测试源码，不执行 TestBackend、fake 或临时目录测试；静态审查不证明运行成功。运行中即时切换不在范围内。

测试和实现不操作用户桌面、不启动真实登录/登出；布局图和 Ratatui 帧足以审查本阶段设计，安装/真实终端另有授权才做。
