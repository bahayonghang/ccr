# 分步实施与验证

三个切片已按顺序实施并验收。各项测试、原生截图与验证范围见 [验收记录](research/acceptance.md)。

1. **共享导航。** 对照 MainLayoutNav 和 MainLayoutChrome，复现当前行同时被选中和聚焦的情况；调整 nav_button、分组、平台标识与底部设置摘要。用现有 `ccr-desktop/tests/native_shell.rs` 检验焦点与选中分离、上下键与 Enter、F6、滚动后的设置入口和状态栏边界。避免修改全局 Kit 按钮风格。
2. **总览。** 重排 overview.rs，使 Overview/Monitoring 仍可切换。把窗口选择器、总量、逐日图、日期和图例组成一个阅读区。用同一个隔离报告核对数值、图柱、窗口和会话标签；另测空窗口、缺库、切换窗口后的加载/失败与旧回包。点击现有 Usage、Commands、Sessions、Install 入口核对目的地。
3. **设置。** 在现有偏好/环境实体之上加入摘要、章节定位和选项反馈。验证键盘操作、选项互斥、语言切换后的菜单和设置摘要、隔离偏好文件重新加载、保存失败与重试。确认退出沿用 close guard，环境/远程入口仍可达。
4. **自动化。** 从 `ccr-desktop/` 运行 `just desktop-fmt-check`、`just desktop-lint`、`just desktop-test-ui`。涉及报告或持久化逻辑时追加 `just desktop-test`。针对本次差异补足已有用例未覆盖的状态。
5. **原生验收。** 从同目录运行 `just desktop-dev`。用常用窗口与相同语言记录两张改后截图。依次检查侧栏选中与焦点、总览窗口和图例、设置选项与摘要，并记录改前/改后证据。若窗口不可观察，逐项标注未验证。Headless 控件测试能证明行为，不能替代本次视觉验收。

检查的重点是新布局能否帮助用户完成三个动作：找到当前页、读懂本机数据、确认偏好已生效。三个切片按边界回退；保留偏好格式和已有深链。
