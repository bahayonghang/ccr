# #247 提供商与账户管理的 Windows 原生验收

在实际 GPUI 窗口中从空页手动开户，核对两个账户的编辑、删除和键盘返回。15 个账户的窄窗里，返回后按一次 Enter 即可重新打开原行。部分批删失败时，界面的逐项结果与库内保留的数据一致。

## 样本与方法

2026-11-25，Windows 11 build 26300，120 DPI，中文，默认字号 14/12。1280×800 浅色与 960×640 深色均为逻辑客户区。私有 Windows 桌面以普通双夹具参数启动，从真实侧栏「签到管理」进入，用 UIA 定位控件、通过窗口消息点击、输入或按键；用 UIA、窗口实图及独立 SQLite 查询交叉核对。JPEG 保留 DWM 窗口框的 1602×1039 或 1202×839 原始尺寸。

## 入口与结果

| 路径 | 观察 |
| --- | --- |
| 空页 → 手动提供商 → 两次开户 | 空页和无效空表单保存后，DB、WAL/SHM、锁、密钥、迁移目录均不存在。手填 `Manual Fixture` 并保存后，连续新增 Aurora Manual、Harbor Manual；两次都进入新增账户详情，编辑器账户名与库中各自新建 UUID 一致，两个 ID 不同且指向同一提供商。[手动开户后的清单](manual-accounts.jpg) |
| 双账户编辑与启停 | A 修改 Session 后取消，原值保留；B 清空 Session 并保存，也保留原值。再只替换 B 的 Session，另一个 Cookie 和 A 的完整 Cookie 均保留。B 的停用、再启用写到同一 ID。界面掩码覆盖 Session 和 API 用户标识。[窄窗掩码编辑器](masked-editor.jpg) |
| 详情、编辑器、来源行 | 960×640 深色下，编辑取消或保存后，同一详情的第一下 Enter 重开原编辑器。A、B 的详情各自返回后，第一下 Enter 均重开来源行。15 行清单中「滚动校验 08」最初不在视区，打开并返回时 Y 为 605→605 物理像素；按一次 Enter 重开，再在编辑器确认账户名。键盘判断按界面到达的目标和焦点圈，等待控件树稳定后发键；未测前台实体键盘或独立读屏器。[长清单来源行焦点](scroll-focus.jpg) |
| 原密钥缺失 | 移走本次夹具生成的原密钥，编辑器保留已知账户名并提示无法读取已有凭据。打开、取消都没有创建新密钥；测试端用留存的原测试密钥核对原 Session 完整。[缺密钥时的编辑器](missing-key.jpg) |
| 提供商目录与定位 | 改名但有稳定内置 ID 的 RunAnytime，旧 NULL 身份的名称 Hotaru、末尾带斜线 URL 的 AgentRouter 均显示「已配置」且按钮禁用；浏览前后身份列逐项相同。另选可用的 Feisakura，库中实际新增。关联入口仅列目标提供商的两个账户，验证状态可打开。有关联账户的提供商确认删除后仍在，显示需先删除关联账户；自定义无关联提供商可改名，取消删除后仍在，再确认才移除。宽窗主按钮从初版 1219 物理像素改为 100×35。[内置身份匹配](builtin-duplicates.jpg) · [关联提供商拒删和按钮宽度](provider-blocked.jpg) |
| 单项与批量删除 | 单项确认显示对象及历史影响，取消保留，确认只清除所选账户和其签到／余额历史。双选批删先取消后确认，报告 2 成功、0 失败并逐项标出名称/ID。另一次故意让数据库拒删 B，报告 1 成功、1 失败；A 的账户、签到、余额行数由 1/1/1 变为 0/0/0，B 保持 1/1/1，未选 C 保持 1/1/0。[部分成功的逐项结果](partial-delete.jpg) |
| 连接诊断和 CDK | 账户详情的「测试账户连接」先显示目标及外部请求说明；进入「CDK 充值」再点「充值」会提示目标和兑换提交后不可取消。分别确认后均显示演示夹具禁止请求提供商。此次没有真实站点请求或兑换结果。[兑换前的目标和后果](cdk-confirm.jpg) |

当前打开的账户被删除后，窄窗返回剩余两行的账户清单，焦点圈落在安全的「重新读取」，下一次 Tab 到达「账户」分段。

十二个场景共读取 197 次 UIA 控件树，检查 Name、HelpText、ItemStatus 和可读的 ValuePattern/TextPattern。所有读取均未出现测试凭据随机标记。各进程 stdout 与 stderr 均为零字节。宿主日志系统、真实提供商响应和其他操作系统不在这次采样范围内。
