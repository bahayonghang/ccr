# Profile 工作台视觉诊断与三方向稿

证据：用户 2026-11-09 提供的 Codex / Claude / Grok Profile 三张宽屏截图（约 160×45 cell，Wide 模式），以及下方源码锚点。

## 1. 现有方向（不做整体换风格）

现有 TUI 已有一致方向：Catppuccin 系深底、平台强调色（Codex 蓝 / Claude 橙 / Grok 灰白）、圆角细边框、左表右详情的「台账工作台」。本任务在这个方向上做增量打磨，不迁移到新风格。

- 视觉论点：安静、精确的终端台账。所有 key/value 对齐同一标签列，层级靠顺序和强调色，不靠装饰。
- 设计签名：行内分节标尺 `─ 用量 · aihub / Codex ──────── 暂无记录`，标题在左、状态在右，一行讲完一个空的分节。
- 交互论点：none。这是键盘驱动、高频切换的界面，任何动画都会读成延迟；反馈全部靠即时状态（选中填充、`~` 待写入、编辑器里的 `•` 脏标记）。

## 3. 三个方向（TUI 版初稿）

三稿都以 Grok `beefapi-google-alter`（无用量、1 次切换）为样例，它是截图里空白最严重的一张。宽度按右栏约 54 列示意。三稿共享第 4 节的通用打磨项。

### 方向 A：存储字段检查器填充（推荐）

逻辑：上方分节压紧、高度稳定；剩余高度交给一个有用的弹性分节"存储字段"，按 profiles.toml 的键名列出这个 profile 实际存了什么（包括目前详情里看不到的 platform_data 字段），密钥只显示"已设置"。超出时滚动。编辑器打开时，这一块就地变成改动预览。

```
╭ 所选配置 ─────────────────────────────────────────╮
│ beefapi-google-alter                    ○ 未生效 │
│ beefapi 商业 Google alter                  #work │
│ ─ 连接 ───────────────────────────────────────── │
│ 模型    grok-4.6            推理    high         │
│ 提供商  beefapi             后端    responses    │
│ 地址    https://beefapi.com/v1                   │
│ 认证    内联 API 密钥        上下文  1000000      │
│ 搜索    是                                        │
│ ─ 用量 · beefapi / Grok ─────────────── 暂无记录 │
│ ─ 启用记录 · 1 次 ────────────────────── 无记录 │
│ ─ 存储字段 · ~/.ccr/platforms/grok/profiles.toml │
│ model                   = "grok-4.6"             │
│ base_url                = "https://beefapi.com/v1│
│ reasoning_effort        = "high"                 │
│ api_backend             = "responses"            │
│ context_window          = 1000000                │
│ supports_backend_search = true                   │
│ api_key                 = ‹已设置›               │
│ tags                    = ["work"]               │
╰──────────────────────────────────────────────────╯
```

- 取舍：多一块信息，信息本身对重度用户有用（核对实际落盘值、发现隐藏字段），且和编辑器天然衔接。代价是要写一个字段投影渲染器，并沿用现有掩码规则（Grok 连掩码都不显示）。

### 方向 B：底部坞站

逻辑：不往右栏塞内容，而是把用量和启用记录移到一条横跨两列的底部坞站，右栏只留身份和连接，列表和右栏同高。

```
╭ Grok 配置 (7) ────────────────╮╭ 所选配置 ─────────────────────────╮
│ ▶○ beefapi-google-alter     — ││ beefapi-google-alter     ○ 未生效 │
│  ○ beefapi-google-main      — ││ 模型 grok-4.6     推理 high       │
│  ...                          ││ 地址 https://beefapi.com/v1       │
╰───────────────────────────────╯╰───────────────────────────────────╯
╭ 用量 · beefapi / Grok ───────────────────╮╭ 启用记录 · 1 次 ─────────╮
│ 请求 —    总令牌 —    估算 —              ││ 上次使用  无记录          │
│ 输入 ·  缓存读 ·  缓存写 ·  输出 ·  推理 · ││                           │
╰──────────────────────────────────────────╯╰───────────────────────────╯
```

- 取舍：彻底消灭右下空白，用量横向展开更好读。代价是坞站固定吃掉 6~8 行，列表可见行数减少；用户现有 25~28 个 profile 在常见终端高度下会开始分页。

### 方向 C：稳定卡片

逻辑：右栏拆成三张独立边框卡片，每张高度与数据无关（用量卡永远画满 5 个类别，没有数据就画 `—`；启用记录卡永远 3 个槽位），最后一张卡伸展到底，并写明"在这个 profile 上按键会发生什么"。

```
╭ 所选配置 ──────────────────────────────╮
│ beefapi-google-alter         ○ 未生效 │
│ 模型 grok-4.6           推理 high     │
│ 地址 https://beefapi.com/v1           │
╰───────────────────────────────────────╯
╭ 用量 · beefapi / Grok ─────────────────╮
│ 请求 —     总令牌 —      估算 —        │
│ 输入 —  缓存读 —  缓存写 —  输出 —     │
╰───────────────────────────────────────╯
╭ 启用记录 · 1 次 ───────────────────────╮
│ 上次使用  —                            │
│           —                            │
│ Enter 应用：写入 ~/.grok 运行时文件     │
│ e 编辑 · o 解绑当前 Grok 配置           │
╰───────────────────────────────────────╯
```

- 取舍：几何最稳定，切换 profile 时完全不跳。代价是大量 `—` 占位本质上还是空，只是被框起来了；底部动作说明和页脚有重复。

## 4. 三个方向共享的打磨项

| ID | 打磨 | 对应问题 |
| --- | --- | --- |
| S1 | 右栏占满分配到的整列高度，底边与列表对齐；内容超出时保留现有滚动与 `x–y / n 行` 指示 | V1 |
| S2 | 各分节的高度只由平台字段集决定，不由当前 profile 有无用量决定；切换选择时分节起始行不变 | V2 |
| S3 | 空分节压成一行：标题在左、状态在右；口径说明（"全时段 · 官方等价美元估算"、"上次使用 = CCR 成功启用"）只在有数据时作为分节副标题出现一次 | V3 |
| S4 | 身份行只显示有区分度的状态：`● 当前` / `○ 未生效`，禁用时才出现 `× 已禁用`；标签显示为 `#work` 并右对齐 | V4 |
| S5 | 右栏内宽 ≥ 64 列时连接字段两列排布（短值配对，URL 等长值独占一行），否则保持单列 | V5 |
| S6 | 运行态条在 Standard/Wide 也压成单行（`运行方式 … │ 当前配置 / 模型 … │ 认证 …`），高度 4 → 3，把一行还给列表 | V6 |
| S7 | "上次使用" 列：无记录显示弱化 `—`；加载中、不可用、时间无效、未来时间保持现有区分 | V7 |
| S8 | 页脚加 `e 编辑`；`x 未设置` 改为 `x 全部字段`；窄屏降级顺序里 `e` 排在 `x`、`o` 之前 | V8 |

## 5. 编辑器的三种承载方式（供后续决策）

| 方式 | 描述 | 取舍 |
| --- | --- | --- |
| 就地右栏 | 按 `e` 后右栏变成表单，左侧列表保持可见但变暗、不可切换 | 和方向 A 衔接最好，看得到上下文；表单宽度受右栏限制（约 50~80 列） |
| 居中模态 | 复用 `overlay.rs` 的暗化底 + 居中对话框，约 72% × 80% | 和现有确认框一致；遮住列表，长 URL / token 输入区更宽 |
| 全屏编辑页 | 临时接管 header 以下区域，左边字段分组、右边改动预览 | 空间最大，适合 Claude 那 15 个以上字段；离开当前上下文感最强 |
