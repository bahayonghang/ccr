# GPUI 工作台留白、设置侧栏与字体字号优化计划

日期：2026-11-12（America/New_York）。基线：本地 `dev`，`3870df6b38ec7f1ce64669fae28918abda3a312f`；开始时工作区干净。状态：**两项原型已获用户批准，GPUI 已实现，核心自动化及 Windows 原生功能验证已完成；源码尚未提交或推送**。

规范地图：[GPUI 工作台留白、设置侧栏与字体字号优化地图](https://github.com/bahayonghang/ccr/issues/162)。地图管理未决事项与依赖；本文件保存截图诊断、源码依据、待验证方案和实施顺序建议，不替代决策票中的最终答案。截图中的端点、配置名和费用不进入示例或测试夹具。

## 1. 目标与已确认需求

目标是让接入状态的占位与它的信息量相称，让全局设置有稳定的页内导航，并让用户能选择本机字体、调整字号。空间利用率不等于把每个像素填满：阅读宽度受控的留白应保留，低信息量面板和横跨屏幕的短选项应收紧。

用户已确认：

1. 界面字体与代码/日志等宽字体分别设置，各有字号。
2. 设置左侧栏点击后滚动定位连续长页对应区块，**不切换成只显示一个模块**。
3. 工作台接入状态采用紧凑摘要与展开详情。

初始范围是计划与决策地图。随后用户先批准制作两个布局原型，再明确要求“按这两个原型实现到 GPUI”，并指定真实本机字体下拉、四项字体偏好独立保存和核心/直接回归验证。该授权替代初始仅规划范围。沿用 `ccr-desktop/DESIGN.md` 的 `style:airy-glass`、静态场景、实色阅读面、语义色和系统字体默认策略。不重新选主题，不扩展到 Tauri 改造、用量业务或环境连接功能。

第 2–6 节保留初始诊断、候选方案与拟验收范围，源码行号指向上述基线，不能据此宣称各候选或每项验证都已完成。最终设计合同以 `ccr-desktop/DESIGN.md` 为准，实际交付及覆盖见第 8 节。

接入状态布局以截图中的 Claude Code 工作台为直接对象；共用组件若影响其他平台，只纳入相应直接回归，不扩大为其他平台页面重设计。

## 2. 截图诊断与源码证据

### 2.1 接入状态占据首屏过多高度

截图一中，接入状态的正文集中在左侧，右侧大片空间没有承载信息；刷新按钮居中独占底部一行。五个短字段纵向堆叠，把更有分析价值的费用和趋势推向下方。

当前代码能解释这一结果：`ccr-desktop/src/features/workbench/claude.rs:116` 的 `claude_status()` 依次添加五个字段、凭据观测、真实性说明和刷新按钮。公共 `panel()` 是全宽纵向容器；外层 `features/workbench.rs:483` 把它放在用量内容之前。没有证据表明这是某个固定高度的单点错误，不能只删除一个 `height` 就宣称解决。

### 2.2 设置结构和控件宽度同时失衡

截图二的顶部 2×2 模块导航抢占垂直空间；主题、语言和退出行为的按钮均分整屏宽度。短选项之间的距离过大，用户需要横跨屏幕比对。

源码对应：`ccr-desktop/src/shell/settings.rs:130` 用 `Section::ALL.chunks(2)` 构造顶部导航；`:152` 后渲染所有设置面板；`option()` 内的 `flex_1()`（`:380`）促成等分拉伸。现有 `locate()`（`:80`）已经支持滚动和标题焦点，适合增量保留，而非重写成另一种页面模型。

### 2.3 Tauri 可借鉴的部分与不能照搬的部分

- `ccr-ui/src/features/configs/AppSettingsView.tsx:23`、`:59`：左侧模块导航＋右侧连续内容，与用户确认的锚点长页一致。
- `ccr-ui/src/features/configs/styles/app-settings.css:56`、`:498`：宽窗使用侧栏，480–1279 时回到顶部 2×2 导航，≤479 时为单列。照搬此断点会在 GPUI 的普通窗口重现投诉，应保留 GPUI 支持范围内的左侧导航。
- `ccr-ui/src/features/configs/settings/AppearanceSection.tsx:133`、`:160` 及 `src/utils/fontPreferences.ts:29`：字体是预设与自定义输入，不能作为“识别本机已安装字体”的实现证据。

### 2.4 字号不是一个全局数值就能解决

`ccr-desktop/src/theme.rs:80` 已调用 `all_font_names()`，证明应用已有本机字体名称目录入口。它本身不证明有等宽分类或字体覆盖检测。

`theme.rs:551` 设置 Kit 的字体、正文 14 和 mono 12；`shell/mod.rs:1156` 又设置根正文像素值，多处标题、元信息、KPI 和代码文本另有显式字号。只改 `Theme.font_size` 会局部生效。主题/系统明暗变化还会重走主题应用路径（`shell/mod.rs:184`），必须避免覆盖用户选择。

## 3. design-atlas 分析

读取本机 design-atlas 0.6.0 的现有设计源、restyle、design-system-core、implementation、anti-slop 和 review-prompt。按已有设计源分支分析，未运行 `route` 或 `apply --force`，未修改现有 DESIGN 合同。

| 维度 | 证据与判断 | 本计划的处理 |
| --- | --- | --- |
| 字体层级 | 标题、正文、说明已有角色，但显式 px 分散，设置没有用户控制入口 | 保留语义层级，补两套字体与字号；梳理字号传播，避免只改 Kit 全局值 |
| 留白 | 接入字段单列；短选项均分宽屏 | 摘要收紧、详情按需展开；表单控件采用有界宽度 |
| 视觉层级 | 接入事实先占大块，趋势被向下推；设置导航与内容争夺竖向空间 | 先识别当前方案和异常，再看用量；模块导航移左 |
| 色彩 | 已有 airy-glass 与实色内容面，不是问题主因 | 不重配色；保持 action/focus/status 区分，不因本机有配置显示“网络正常” |
| 动效 | 静态截图无法判断时序 | 不新增装饰动画；锚点可直接定位，展开/字体变化保持焦点 |
| 微交互 | 刷新已有 busy/disabled；截图不能证明键盘与滚动跟随 | 保留刷新状态，定义 disclosure、字体选择、恢复默认、保存失败与焦点回退 |
| 自适应 | 两张宽窗截图不足以证明默认/最小窗口；Tauri 的窄窗退化已由源码确认 | 在 GPUI 支持范围内维持左侧栏，先减少列再收缩文字；正文不横向溢出 |
| 产品特征 | 多平台配置、凭据观测、真实用量是有效信息；空白不是新增指标的理由 | 用对齐和顺序提升密度，不添加填充卡片、假指标或重复说明 |

重点 judged gates：3（避免同形卡墙）、40/41（对比度与成对文字色）、44b（首屏主任务）、73（内容不遮挡）、DA1（不重复文案）、DA2（不隐藏必要说明）、DA3（字号层级）、DA5（低频选项不挡主任务）。原生 GPUI 不适用 DOM/ARIA/CSS 的机械判定，须使用现有 AccessKit/控件语义。

`slop_check.mjs` 的文档扩展名不含 `.rs`。显式调用导出的 `run()` 后得到 `files: 0`、`floorFail: 0`、`houseFail: 0`、`reflex: 0`；这是零文件覆盖，**不算 Rust/GPUI 机械扫描通过**。这里只完成静态分析；新方案的原生视觉、键盘、字号与字体 fallback 尚未验收。

## 4. 布局提案（待原型定稿）

### 4.1 工作台：内容高度的摘要带

以下是结构示意，尖括号为占位，不是运行数据：

```text
接入状态  <当前运行方案>  <凭据观测状态>       [刷新状态] [展开详情 ▾]
端点 <安全主机名>       模型 <真实值或未观测>
本机配置与凭据观测不证明网络可用；API 接入不要求保存官方账户。
──────────────────────────────────────────────────────────────
用量来源与新鲜度 → 费用读数 → 趋势与模型分布
```

- 方案名是摘要内的主要识别信息；已知状态与异常用明确文字，不用绿色点推断网络可用。
- 刷新和详情开关放在摘要头部右侧，按内容宽度，不再单独居中占一行。保留 `workbench-refresh` 和原有忙碌/禁用语义。
- 常显候选：当前方案、端点主机、模型、凭据观测摘要和真实性说明。供应商、认证方式及既有完整观测放入可展开详情，具体优先级由原型确认。
- 保留 `safe_host()`，不将带凭据 URL、token 或秘密写进标签、tooltip 或日志。错误和凭据缺失摘要常显，不依赖 hover 或展开才能发现。
- 默认按内容高度排版，目标是少量摘要行；不设强制两行高度。长中英文、未知值和较大字号允许换行，优先保证真实性说明完整。
- 宽窗可横向组织，窄窗折行为字段组；展开在同一阅读面内，用 hairline 与对齐分隔，不新增嵌套玻璃卡片。
- 详情默认折叠，原型先采用会话态；不为了此优化扩展持久化配置。折叠隐藏已聚焦内容时，焦点回到详情开关。

验收重点：收紧后用量内容确实上移；不能通过删除必要说明、截断错误或新增假状态实现。

### 4.2 设置：页头＋左侧锚点栏＋右侧长页

```text
全局设置                                      <主题/语言/版本摘要>
┌──────────────┬───────────────────────────────────────────────┐
│ 外观         │ 外观                          [有界分段选择]   │
│ 字体与字号   │ ───────────────────────────────────────────── │
│ 语言         │ 字体与字号                                    │
│ 工作台偏好   │ 界面字体       [搜索本机字体 ▾]                │
│ 诊断与环境   │ 界面字号       [−] <数值> [+] [恢复默认]       │
│              │ 代码/日志字体  [搜索本机字体 ▾]                │
│              │ 代码/日志字号  [−] <数值> [+]                 │
│              │ <中文/英文/数字预览；代码对齐预览>             │
│              │ ───────────────────────────────────────────── │
│              │ 语言 / 工作台偏好 / 诊断与环境                 │
└──────────────┴───────────────────────────────────────────────┘
```

候选几何来自现有间距体系，**是原型起点，不是已批准硬尺寸**：页内侧栏 176 logical px，最小窗口可收至 144；栏间距 16/24；正文阅读宽度候选上限 960；字体选择控件约 240–320。主页面全局侧栏继续使用现有 216/184 规则，不借机重做整个外壳。

- 页头与模块侧栏固定，右侧长页为主滚动容器。左侧是页内导航，不是另一套全局目的地或平台 tab。
- 首选把“字体与字号”做独立锚点，方便直达；也可在外观内分组后仍给侧栏定位入口。原型决定最终分组，避免同一选项重复出现。
- 表单行左侧为标签及必要说明，右侧为紧凑控件；主题/语言/退出选择不再 `flex_1` 均分正文宽度。宽屏可以保留右侧有目的的留白，不用拉长控件补满。
- 手动滚动时更新当前区块高亮；程序定位后不能立即被旧坐标回调反向覆盖。到底部时最后区块可正确选中。
- 字体/字号变化、展开详情、诊断内容变化后重取布局边界；不依赖旧的固定像素偏移或渲染轮询。
- 点击导航沿用标题 focus anchor，键盘继续进入目标内容；保留 `settings-nav-*` 与 `open_environment_settings()`。新增字体锚点后调整索引，避免环境深链定位到错误项。
- 最小受支持 960×640 仍维持左侧栏，先收缩留白和控件宽度、让说明换行；不自动退回顶部 2×2。大字号适配失败时先调整表单布局，不暗中降低字号。

### 4.3 字体与字号：识别、选择、生效、回退是一条完整链

| 能力 | 建议方案 | 需定稿或验证 |
| --- | --- | --- |
| 本机字体目录 | 复用 GPUI text system；初次进入相关设置时取得并缓存可用家族名，去重排序；两个选择器共享目录 | 以锁定 SDK 的 API/调用线程为准，不在 render 内重复枚举 |
| 选择控件 | 可搜索下拉；稳定的“系统默认”入口、当前值、无匹配/读取失败状态；键盘 Enter/Esc/方向键与关闭回焦 | 复用 Kit 已有控件，确认弹层不被滚动区裁剪 |
| 界面/等宽分离 | 界面字体用于正文/控件；代码、日志、路径、命令与编辑区遵循独立 mono 角色 | 统一 API 没有完整可靠的等宽分类；共享目录＋预览是最小候选，“只列等宽”是否增加平台适配由最终合同决定 |
| 字号 | 分别设置 UI 基准和 mono 字号；显示明确数值与默认值，提供预览和恢复默认 | UI 12–20、mono 11–20、步长 1 为讨论候选；须在原型中确认范围及语义字号传播 |
| 即时应用 | 选择后预览与当前窗口文字及时变化；沿用异步偏好保存和失败反馈，不对可逆设置额外确认 | 滑动/连续输入期间的提交节奏和焦点稳定性 |
| 缺失字体 | 保存的家族名与有效回退分开显示；回退到系统字体并给出可见原因，允许恢复默认 | 重启后字体被卸载、字体目录为空、不支持字符时的行为 |
| 字符与数字 | CJK/符号沿用 fallback；金额等继续请求 `tnum` 并右对齐；代码预览显示对齐 | 不宣称任意用户字体都支持 `tnum` 或所有中文字符 |

预览使用中性静态文案和明确示例：中文/English、大小写、数字与标点，代码预览只检验可读与对齐，不填入用户配置或伪装真实运行结果。恢复默认只重置字体和字号，不重置主题、语言、退出偏好和窗口位置。

锁定版本的 API 事实已由[字体能力研究票](https://github.com/bahayonghang/ccr/issues/165)解决；完整出处和限制保存在[独立研究报告](https://github.com/bahayonghang/ccr/blob/b7b1d67fb63d5e79a9e2b79dc148338585e4d6ca/.trellis/research/gpui-font-preferences-api-research.md)。这些事实支持实施路线，不代表布局或字号政策已获原型确认。

## 5. 技术边界与实施路线建议

以下是决策收敛后的建议顺序，不是本轮新增实施票或实施授权。按影响范围拆分，优先复用 owner，不建立通用设计平台。

| 顺序 | 预计改动 owner | 完成条件 |
| --- | --- | --- |
| A. 定稿设计合同 | `ccr-desktop/DESIGN.md` 的 Layout/Typography/Components；现有字体 token 层 | 把已确认的原型和字号传播写成短合同，保留原生与可访问性限制 |
| B. 收紧接入摘要 | `features/workbench/claude.rs`，必要时局部调整 workbench 组合 | 摘要/详情/刷新/异常均可达，图表上移，原有安全语义不变 |
| C. 设置布局 | `shell/settings.rs`、必要的 `theme.rs` 几何 token | 左侧锚点导航和右侧长页，紧凑表单、手动滚动高亮与环境深链通过 |
| D. 字体偏好与应用 | `runtime/preferences.rs`、`shell/preferences.rs`、`shell/window_state.rs`、`shell/mod.rs`、`theme.rs` | 兼容旧偏好，主题/系统变化和窗口保存不丢字体，失败反馈真实 |
| E. 受影响文字角色 | 现有 body/meta/title/mono 消费处和对应固定/虚拟行 | 实际字号覆盖与声明一致；行高和 stride 同步；不破坏选择、滚动或输入草稿 |
| F. 聚焦回归与原生验收 | `tests/native_shell.rs`、偏好单测及对应现有 UI tests | 自动化和原生覆盖分开报告，必要证据齐全后再报告实施完成 |

偏好实现特别注意：

- `DesktopPreferences` 目前为 `Copy`。任意字体名需要拥有字符串；调整现有 by-value/解引用调用，不以固定枚举假装本机全量字体。改动追到窗口几何/关闭保存路径，不能漏掉 snapshot 字段。
- 旧 JSON version 1 缺少字体字段应继续可读，并取现有系统字体/UI 14/mono 12 默认；是否沿用 v1 可选字段由最终合同确认，不为此强制清空旧文件。
- 保留 16KiB 上限、重定向拒绝、不可读/较新文件保护、`AtomicWriter`、generation 与工作线程边界。坏字体字段的处理不可顺手破坏其他已读偏好。
- 字号传播要区分文字与结构：语义标题/说明应保持层级，mono 独立；图标、窗口尺寸和图表画布不自动等比缩放。固定/虚拟列表若随文字增高，实际行高、stride、可见范围与命中区必须同源。
- 先列出受影响的硬编码字号和字体消费处，再做角色替换；不以全仓格式化或不相关布局重构扩大 diff。

## 6. 验证与成功标准

本轮只做规划文档、源码核对和地图关系校验；不运行产品全量测试、不启动原生窗口。下面是后续实施应执行的检查。

| 核心路径 | 可判定的成功标准 |
| --- | --- |
| 摘要/详情 | 默认收紧；展开/折叠可键盘操作且回焦正确；长方案名/端点、未知模型、无凭据、读取失败和在途刷新不丢信息、不假装连通 |
| 设置导航 | 导航在左；点击、手动滚动、到底、改变字号后高亮和目标一致；环境深链及标题焦点保留；正文无横向溢出 |
